# 32nd Notes by Splitting Cells — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any 16th cell can be split by holding it into two 32nd halves, and per-beat triplets are removed.

**Architecture:**
- The beat model stops having a subdivision. Each track keeps its four 16th values in `Beat.cells`, and a parallel `Beat.splits` holds `null` (whole cell) or the right half's velocity.
- The tick grid becomes 8 ticks per beat (32nds), and every consumer (playback, MIDI, notation, share links, thumbnails, grid) reads halves from that model.
- Old triplet data is converted to the nearest 32nds wherever it is parsed.

**Tech Stack:** React 19, TypeScript, Zustand plus Immer, Vitest with Testing Library (jsdom), Playwright, VexFlow 5.

**Spec:** `docs/superpowers/specs/2026-11-09-32nd-notes-design.md`

## Global Constraints

- **Layout:** phone first, in landscape. All default rows must still fit at about 750×340, and rows stay at least 24px tall. Desktop and mouse input must also work.
- **Values:** hold time `LONG_PRESS_MS` = 450 (already in `src/ui/gestures.ts`). New right-half notes are 40 and other new notes are 100. `GHOST_MAX` stays 45 and `ACCENT_MIN` stays 110.
- **Toast copy (exact):** `Triplets were replaced by the nearest 32nds`
- **Storage rule:** the previous version must still read saved projects as plain 16ths. `Beat.cells[track]` stays 4 numbers, the new data goes in a field the old parser ignores, and `div` is not written.
- **Gates for every task:** `pnpm test`, `pnpm typecheck` and `pnpm build` are green. `pnpm e2e` is green from Task 6 on, and any e2e test a task breaks is fixed in that task.
- **Commits:** single-line conventional subjects with no trailers, made straight to `main`. Do not push.

## Review Focus

1. **A hold that fires after Follow moved the view to another bar** must split the cell in the bar where the press started. Covered in Task 3.
2. **A hold interrupted by `pointercancel`**, for example iOS taking over a scroll, must not split. Covered in Task 3.
3. **Notation for any mix of cells and halves** must add up to exactly one quarter per beat, or VexFlow draws a broken bar. Covered in Task 4.
4. **Malformed `splits` in stored data or old links** (wrong length, strings, out of range) must repair, not crash. Covered in Task 1.
5. **Merging a cell drops its right-half note.** Undo must bring it back exactly. Covered in Task 3.

- [ ] **Step 3: Implement the model**
  - **`convertTriplets`:** cell `i` goes to 32nd slot `Math.round(i * 8 / div)`. Slot `s` is cell `s >> 1`, half `s & 1`, and the louder note wins.

- [ ] **Step 3: Implement**

The 8 slots per beat come from `velocityAt`. Onsets and durations follow today's rule: a note lasts to the next onset or to 8. Each span is cut into pieces like this:

```ts
const DUR: Record<number, NoteDur> = { 1: '32', 2: '16', 3: '16d', 4: '8', 6: '8d', 8: 'q' };
// Spans of 5 or 7 are split at the half beat (slot 4); every other length is one piece.
const pieces = (start: number, end: number) => (end - start === 5 || end - start === 7 ? [4 - start, end - 4] : [end - start]);
```

- A note span becomes a note with the first piece, then a rest with the second piece if there is one.
- A leading rest is cut the same way.
- In `renderNotation`, `16d` is dotted like `8d`, and the tuplet drawing code is removed.
